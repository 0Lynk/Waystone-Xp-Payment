# 流体四边形的绕序与贴图朝向

日期：2026-11-01
分支：`fix/fluid-quad-winding`

## 改了什么

1. 新增 `src/main/java/com/olynk/waystonexppayment/client/TankFaces.java`：把液面的五个面（四侧 + 顶）抽成一个纯几何构造器，输入六个参数（内腔近/远边、液面高度、贴图 u0/u1、两条 v），输出四个角点与外法线。角点顺序固定为「先下后上」，`u` 指向**站在罐外的人看到的右手边**。
2. `XpPaymentTankRenderer#draw` 改用 `TankFaces`，删掉原来的 `quad(...)` / `vertex(...)` 两个私有辅助。
3. 新增 `src/test/java/com/olynk/waystonexppayment/client/TankFacesTest.java` 四例：绕序叉积必须与外法线同向、`u` 必须朝屏幕右方递增、侧面必须先给下边、顶面必须从南边起。

## 为什么改

机主在游戏里看到液面的贴图是反的：从外面看是「背面」，从里面看反而是「正面」。

## 根因

上一版 `draw` 里四个侧面的顶点是这样排的（以北面为例）：

```
(near, near, near) → (far, near, near) → (far, top, near) → (near, top, near)
```

两个错误叠在一起：

- **绕序反了**。站在罐外（-z 方向）看向 +z，屏幕右方是 **-x**。按上式从外看是「右下 → 左下 → 左上 → 右上」，也就是顺时针；叉积算出来的几何法线指向 **+z（朝罐内）**，而 `setNormal` 声明的法线是 `(0,0,-1)`（朝罐外）。两个法线不一致，正面就落在了内侧。
- **`u` 也反了**。`u0` 挂在 `near`（x 小）上、`u1` 挂在 `far`（x 大）上，而从外看屏幕右方是 -x，于是贴图左右镜像。

因为是 `RenderType.translucent()`（不剔除），两个错误都不会让画面消失，只是看起来「里外颠倒」——所以只能靠眼睛发现，测试也一直没覆盖到。

## 改动前后对比

| 面 | 之前 | 现在 |
|---|---|---|
| 北 | `near→far`，`u0` 在 near | `far→near`，`u0` 在 far，绕序 CCW |
| 南 | `far→near`，`u0` 在 far | `near→far`，`u0` 在 near |
| 西 | `near→far`（z 递增） | 保持 z 递增，但 `u0/u1` 对调 |
| 东 | `far→near`（z 递减） | 保持 z 递减，但 `u0/u1` 对调 |
| 顶 | 从北边起、绕序 CW | 从南边起、绕序 CCW，`v0` 在北 |

## 备选方案

- **a. 只在渲染器里把四组顶点顺序对调**：最小改动，但每改一次模型就要手工推一遍四个面，而且没有测试守着——这次就是这么错的。
- **b. 用 `pose.scale(-1,1,1)` 镜像整个液面**：会连法线一起翻，光照变暗，且顶面也会被镜像。
- **c. 换 `translucentCullBlockSheet()`（EIO 的做法，开剔除）**：绕序错了液面直接消失，反而更容易发现；但看不见罐内壁，且水流从下方看不到。
- **选 a 的加强版**：抽出 `TankFaces` + 几何测试，绕序和 `u` 方向各有一条断言，改模型时先跑测试。

## 意外点

- `TankFaces.Side.values()` 里五个面用同一个循环渲染，顶面只换两个 v 参数——第一版循环里把顶面也当成侧面（`bandTop`），会让顶面只取贴图底部一条。现在用 `isTop ? sprite.getV(0F) : bandTop` 分开。
- 叉积断言用未归一化的法线除以长度后再比，避免依赖 `assertEquals` 的 delta 选值。

## 验证

- `.\gradlew.bat test --offline` → **29 suites / 179 tests / 0 failures**（175 → 179）。
- 负向验证：把北面两个角点换回旧顺序（`u0` 挂 `far`）→ `everyFaceIsWoundCounterClockwiseSeenFromOutside` 与 `theSpriteRunsLeftToRightForSomeoneStandingOutside` 两例红，其余绿；恢复后全绿。

## 未覆盖

- 只有几何层面的证明，**没有实机截图**——渲染结果仍需机主在游戏里看一眼（尤其是从罐内往外看时贴图是否正）。
- 顶面的 `v` 方向按原版约定（north → v=0）推导，实机若发现上下颠倒需再对调一次。
