# 模组图标（mod icon）

日期：2026-10-11
依据：`src/main/resources/META-INF/neoforge.mods.toml` 的 `logoFile` 声明；画面配色取自既有贴图 `src/main/resources/assets/waystone_xp_payment/textures/block/xp_payment_tank.png`

## 改了什么

**资源**

- 新增 `src/main/resources/waystone_xp_payment.png`：256×256 不透明 PNG，4,715 字节，
  sha256 `faeb74a0da9f42177de990fa761e333f933dbda4e3c8b1a8e60284518673e2ef`。
  文件名与位置跟 `neoforge.mods.toml:12` 的 `logoFile = "waystone_xp_payment.png"` 完全一致，元数据无需改动。
  画面内容：石地上的灰色传送石碑，碑面刻一枚发光的绿色菱形符文，正下方是装满绿色经验流体的玻璃储罐，
  四周漂浮经验球，背景是带暗角的洞穴。素材全部取自本模组自己的三种颜色
  （流体 `#56D67C`、外框 `#3A4046`、玻璃 `#5C626A`）并扩展了高光与暗部。

**工具**

- 新增 `tools/make_icon.mjs`：图标生成脚本，只用 Node 自带模块（`fs`/`zlib`/`crypto`，手写 PNG 编码器），
  无第三方依赖。在 64×64 逻辑网格上作画，最近邻放大 4 倍输出 256×256，
  用法 `node tools/make_icon.mjs <输出路径>`，跑完打印尺寸、字节数与 sha256。

**文档**

- `CHANGELOG.md` 顶部新增 `## Unreleased` 段（Added：Mod icon；Tests：55 个单测不变）。

## 为什么改

`logoFile` 从第一个版本起就指向 `waystone_xp_payment.png`，但这个文件**从来没有存在过**
（改动前 `Test-Path src\main\resources\waystone_xp_payment.png` 为 False，`git log --all --diff-filter=A` 为空），
所以模组列表和模组详情页一直没有图。这次把这份悬空的元数据补实。
图标内容刻意只讲本模组的两件东西——石碑与经验流体储罐——并复用储罐贴图的配色，
让它跟方块放一起不违和。

## 未验证

- `[NEEDS VERIFICATION: 模组列表 / 模组详情页里的实际显示效果]` 需要在客户端里看，只有机主能做；
  本地只验证到「图标按原字节进入 jar、`logoFile` 指向正确」这一层。
- `[NEEDS VERIFICATION: 小尺寸观感]` 只在 256 / 64 / 32 / 16 四档做过最近邻缩放自查，
  16×16 下细节会糊成轮廓（石碑+储罐的剪影仍在），没有在真实游戏里按实际缩放贴图核过。

## 自定夺

- **生成脚本入库**，而不是只丢一张二进制图片：图标是可复现产物，脚本同时充当「这张图怎么来的」的说明。
- **不改 `README.md`**：用户要的是模组图标（模组列表用的 logo），仓库首页不强行插图。
- **不发新 Release**：0.2.0 已发布，本次改动落在 main 上、随下一次发版出去；
  已发布的 v0.2.0 资产保持不变（其 jar 内没有这张图标，属正常）。
- 测试实例：把本次构建的 jar 放进 `mods/`，让机主重启后能直接看到图标。
  实例里那份已发布的 0.2.0 jar 早先已被改名成 `waystone_xp_payment-0.2.0+mc1.21.1.jar.disabled`
  （不是本次改的），所以没有覆盖任何生效中的正式资产；正式资产仍以 GitHub Release v0.2.0 为准。
