# 2026-10-10 实机冒烟与储罐 NBT 修正

## 改了什么

- `block/entity/XpPaymentTankBlockEntity.java`：`saveAdditional` / `loadAdditional` 不再把
  `FluidTank.writeToNBT(...)` 的返回值塞进额外的 `tank` 包裹层，而是把**本方块实体自己的 tag** 交给
  FluidTank 助手（`tank.writeToNBT(registries, tag)` / `tank.readFromNBT(registries, tag)`）
- `docs/verification.md`：第 3 节从"被环境阻塞"改写为实机冒烟记录（含 RCON 原始输出），并新增"本次冒烟
  **未**覆盖"清单
- `CHANGELOG.md`：Known limitations 里"尚未冒烟"一条替换为真实结论（哪些已验证、哪些仍需要玩家/GameTest）

## 为什么改

1. 用户要求再做一次实机冒烟。此前 `maven.neoforged.net` 不可达，`gradle runServer` 缺 `DevLaunch` 与
   `moddev-config` 而失败；本次该主机恢复，可以真正启动开发服务器。
2. 冒烟中发现：储罐的流体 NBT 采用 `{tank:{Fluid:{...}}}` 这种多套一层的布局——自身能存能读，但用原版
   `/data` 命令读写时路径与惯例不符。既然还没发布，直接改成通用布局比留兼容层更划算。

## 改动前后对比

| | 改动前 | 改动后 |
|---|---|---|
| 流体持久化 | `{tank:{Fluid:{id,amount}}}`（多一层 `tank` 包裹） | `{Fluid:{id,amount}}`（NeoForge `FluidTank` 惯例） |
| `/data merge` 灌流体 | 需要猜嵌套路径，且先用错 key 试了两次才成功 | `data merge block <pos> {Fluid:{id:'…',amount:1000}}` 直接生效 |
| 冒烟状态 | 阻塞（无实机证据） | 通过：服务器启动 + 模组加载 + RCON 直查区块实体 NBT + 数据包速率装载 |

## 根因分析与教训

1. **先查 API 源码再猜 NBT 键名**：`FluidTank.readFromNBT` 读的是 **`nbt.getCompound("Fluid")`**，
   `FluidStack` 的键是 `id`/`amount`（源码：`build/moddev/artifacts/neoforge-21.1.8-sources.jar` 里的
   `FluidTank.java:62-69`、`FluidStack.java:61-66`）。我先前按"tank"猜，导致 RCON 灌不进去（现象是
   `tank: {}`），浪费了两轮试错。教训：**能用反编译源码确证的外部契约，不要用试错去逼近。**
2. **`/data` 命令是很好的运行时探针**：它能同时验证"方块/BE 已注册""自定义 NBT 真在存""save/load 往返
   正常"，而这些是日志看不出来的。RCON 让无客户端环境也能这么做。
3. **冒烟测试的价值不是"证明代码没崩"，而是发现只有运行起来才暴露的缺陷**：本次唯一发现的缺陷
   （NBT 多一层包裹）编译期与单元测试都看不见。
4. **`data merge` 写入未知结构时我们选择静默忽略**：冒烟里写 `players:['0Lynk']`（字符串列表）没有被
   读入，因为 `AccessList.load` 只接受复合标签条目。这是有意的防御性行为（不因外部数据格式不对而崩），
   已在此记录以免日后误判为 bug。
