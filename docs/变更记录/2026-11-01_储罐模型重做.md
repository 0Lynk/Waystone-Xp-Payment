# 储罐模型重做：从纯色方块换成玻璃骨架罐

- 日期：2026-11-01
- 范围：`assets/waystone_xp_payment/models/block/xp_payment_tank.json`、`textures/block/xp_payment_tank_frame.png`、`textures/block/xp_payment_tank_glass.png`；删除 `textures/block/xp_payment_tank.png`

## 改了什么

机主在 Blockbench 里做的罐子模型（`D:\Desktop\model`）有六处问题，逐条修掉后入库：

| # | 原模型 | 现在 |
|---|--------|------|
| 1 | 6 块玻璃是零厚度平面（`from`/`to` 两点同值），只能看见一面 | 每块给 0.02 厚度，五面（四侧 + 底），可以两侧都看见 |
| 2 | 贴图引用是裸名 `texture` / `texture1` | 改成 `waystone_xp_payment:block/xp_payment_tank_frame` / `..._glass` |
| 3 | 没有 `parent` | `minecraft:block/block`（顺带给到物品栏、地面、手持的 display 变换与 `gui_light: side`） |
| 4 | `texture_size` 写 64×64，实际贴图是 32×32 / 64×64 | 两张贴图统一 16×16，模型不再声明尺寸 |
| 5 | UV 大幅拉伸（16×1.5 的横梁用 0.75×8 的 UV 区域） | 所有面 `uv: [0,0,16,16]`，靠密铺而不是拉伸 |
| 6 | `model.json:64` 写成 `14.6` | 14.5，与其它三根立柱对齐 |

另外三处是我按经验加的：

- 玻璃改用 `render_type: minecraft:cutout`——贴图只有全透明与不透明两种像素，不需要 `translucent` 排序，也不会挡住后面的方块。
- 删掉顶部那块平面：液面将来由 block entity renderer 画，留着会把它盖住，而且从上方看不到罐内。
- 骨架沿用机主给的 12 根（4 根立柱 + 上下各 4 根横梁，厚 1.5），只把颜色从 `#3F3F3F` 的整片纯色换成带纵向渐变与四角铆钉的 16×16 贴图。

## 为什么

原模型直接放进资源包会有三个立刻可见的后果：玻璃只有一面能看见（从外面看向罐内会看到透明）、物品栏里的罐子没有正确的旋转与缩放（缺 `parent`）、贴图路径无效（裸名）。这三点都不是美术问题，是导出后必须手补的模板字段。

## 备选方案

- **a) 零厚度 + 复制翻转另一面**：能省 4 个面，但镜像面要单独配 UV，且两面之间会有 0.001 的 z-fighting 风险，改起来比加厚度更难对。
- **b) 只做外壁、内壁交给方块自身的背面**：Minecraft 面剔除按 `cullface` 判定邻居遮挡，不是背面剔除，透明模型的内侧本来就会画，方案 b 不解决问题。
- **c) 保留顶部平面**：从上方看是一个封闭罐，但液面渲染必须在它下面，等于把液面藏起来。选了删掉。

## 意外点

- `minecraft:block/block` 里确实带着 `display` 全套变换与 `gui_light: side`（从客户端 jar 的 `assets/minecraft/models/block/block.json` 读到），所以只写一句 `parent` 就把物品栏、手持、掉落物三种绘制都修好了；`cube_all` 反而只是个贴图别名外壳，没有 display 信息。
- 模型 JSON 用 Python 生成（`json.dump(indent=2)`）后是 18 KB，比手写大得多——可读性换文件体积，1.21 的资源加载器不在乎这点尺寸。

## 验证

- 17 个元素（12 骨架 + 5 玻璃），无零厚度元素，坐标全部落在 0–16。
- 模型 JSON 可被解析，`parent` / `render_type` / `textures` 三项齐全。
- `.\gradlew.bat build --offline` → `BUILD SUCCESSFUL`，jar 204,512 B，内含 `models/block/xp_payment_tank.json`（18,467 B）与两张新贴图，旧贴图已不在包里。
- 用等轴测预览（Python + Pillow，一次性脚本，不进仓库）渲染过骨架 + 玻璃 + 半透明液面的组合，结构正确。

## 未覆盖

- **没有在游戏里看过**：模型是资源文件，服务端冒烟测不到渲染。需要机主进游戏看一眼（尤其是玻璃边缘是否有 z-fighting、骨架明暗是否够分）。
- 液面渲染还没做：罐内流体目前不可见，要等 block entity renderer（已调研：按 Ender IO 的做法自绘 UP + 四侧 5 个面）。
- 两张贴图是我画的占位版（16×16 灰金属 + 全透明玻璃），机主可以随时换成自己的美术。
