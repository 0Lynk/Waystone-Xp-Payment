# 评审问题清单与测试流程

日期：2026-10-16
版本：0.2.0（文档改动，不改代码）

## 改了什么

- 新增 `docs\问题修复清单.md`：把三位专家（验收测试工程师 / 遗留系统工程师 / 软件架构师）的只读评审结论与主会话自查合成一份「问题 → 怎么改 → 预期成果（验收标准）」清单，分 R1 阻塞级、R2 一致性、R3 经济与安全、R4 文档与账目、R5 清理，外加"流程（主会话自身）"五条。
- 新增 `docs\测试流程.md`：L0–L5 六层测试流程、A–I 九组共 50+ 条用例（每条含步骤 / 预期 / 证据要求）、三条历史缺陷的回归清单、最小可上线门槛、玩家侧反馈模板、以及"当前已知预期失败"清单。

## 为什么改

评审暴露的问题此前只存在于对话里：仓库既没有"哪些是已知缺陷、准备怎么修"的清单，也没有可执行的测试流程，机主无法据此做实际测试，下一个接手者也无法核对进度。

## 改动前后对比

| 之前 | 之后 |
|---|---|
| 缺陷散落在三份专家回报与会话记录中 | `docs\问题修复清单.md` 单点汇总，每条带 `文件:行号` 与验收标准 |
| 测试只有"55 个单测"这一句声明，覆盖边界（5 类 / 8.8%）无人写明 | `docs\测试流程.md` 写明分层、用例、证据要求与放行门槛 |
| 玩家想帮忙测试时没有可执行的步骤 | 用例可直接照做；不通过时按模板回填即可 |

## 根因分析

- 之前每一轮只做"本轮自检"（构建绿、单测过、jar sha 一致），没有跨轮不变量（单一真值源、协议版本常量、产物身份、文档与源码一致），也没有把评审结论变成仓库资产。
- 测试边界按"能不能无头跑"划，而不是按风险划 —— 三次真实缺陷（mixin `@Shadow`、空 `FluidStack` codec、NBT 嵌套）全部落在纯函数单测之外。

## 未验证 / 存疑

- 本清单里的行号基于 2026-10-16 的工作区状态，代码一旦改动即会漂移；因此每条同时写了验收标准，不依赖行号。
- `D-2` 的"挖掉储罐掉落为空"是**静态判断**（`src\main\resources\data\waystone_xp_payment\` 下只有 `recipe\`，全仓无 `loot_table` 文件、无 `noLootTable()` 调用，方块类无掉落覆盖），需实机确认 —— 已列入测试用例 C8。`[NEEDS VERIFICATION]`
- 报告未逐条复现 `E-1`–`E-6`：这些都是读代码得出的结论，需要按测试流程在游戏里验证。

## 自定夺

- 文档放在 `docs\` 根目录（沿用 `docs\界面规格-第三轮.md` 的中文命名习惯），未写进 `docs\verification.md` 的附录 —— 那份文件的定位是"已完成的验证证据"，待修清单混进去会让两者都失去意义。
- 本轮**不修**任何代码缺陷：先让清单与流程可执行，再由机主按流程做一轮实测，之后按 R1→R5 分批修。
- 未把 `docs\问题修复清单.md` 里的 R5 死代码清单直接改掉：删除属于代码改动，应单独一轮 + 单独 PR。
