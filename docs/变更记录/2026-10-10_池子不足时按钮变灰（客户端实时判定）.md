# 2026-10-10 池子不足时按钮变灰（客户端实时判定）

## 改了什么（全部在客户端预览侧，服务端逻辑未动）

- `block/entity/XpPaymentTankBlockEntity`：
  - 新增 `cachedPoolXp`（在 `onContentsChanged` 与 `loadAdditional` 时重算）与 `hasSyncedData`（收到过任何数据即 true）；
  - `poolXpForClient()` 改为：**本地按同步到的流体量现算优先**，只有在本地算不出（数据包配方声明的流体、客户端速率表不认识）时才回退到服务端同步来的数值。
- `client/ClientFluidPaymentRequirement`：新增 `payer`（可为 null = 已知有罐但此处无法检查）；`canAfford` 现在**镜像服务端拆分**——`PaymentSplit.compute(costXp, poolXp, 1, player.totalExperience).affordable()`，罐不够付这一次就返回 false（按钮灰）；`payer` 无数据时保持放行（交给服务端）。
- `client/XppClientRequirements`：
  - 新增三态查找 `TankRef`（① 方块实体已加载 ② 只在客户端登记表中存在 ③ 无）；
  - 付款方选择与服务端同序：来源罐"非空"优先，否则目标罐；**空罐不算付款方**（与服务端 `payerAt` 的空罐返回 null 一致）；
  - 日志补上池值与"区块未加载、交给服务端"的区分。
- 新增客户端 mixin `mixin/WaystoneButtonClientMixin`（已登记进 `waystone_xp_payment.mixins.json` 的 `client` 段）：在 `WaystoneButton#renderWidget` 头部重算一次我们的需求，不够付就 `active = false`。**只置灰、不点亮**（Waystones 也会因"目标就是当前石碑"等原因主动置灰，不能被我们覆盖）。
- 重建并覆盖到测试实例（见回复中的字节数与时间）。

## 为什么改

用户实测反馈：把罐里的流体抽走后，界面里的其他石碑**仍然可点击**，点了不传送；离开界面再进来还是一样。期望行为是"**罐里不够付这一次就把按钮变灰**"。

成因是上一轮为修"毒化 bug"所做的取舍：客户端判定只问"两端有没有罐"，不问罐里有多少。现在按用户确认的方案，把"罐里有多少"重新纳入判定，但改用不会重蹈毒化的方式：从**同步到的流体量现算**，而不是缓存一个可能过期的服务端标量；并且**"未知"永远不判灰**。

## 改动前后对比

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 罐里够付 | 可点 ✅ | 可点 ✅ |
| **罐里不够付这一次** | 可点但点了失败/回退玩家 ❌ | **按钮变灰** ✅ |
| 界面开着时把流体抽走 | 一直可点 | 下一次渲染即变灰 ✅ |
| 目标石碑区块未加载（只有登记表知道有罐） | 可点（服务端裁决） | 不变 ✅（避免毒化重现） |
| 方块实体已加载但数据还没到 | 可点 | 不变 ✅（"没有信息"≠"空"） |

## 性能影响（用户问到的点）

| 关注点 | 结论 |
|---|---|
| 是否有每帧计算 | 有，但只在**图标渲染**与**按钮渲染**两处；`canAfford` 只做"读一个缓存 int + 一次整数比较"，因为池值缓存在方块实体里、仅在内容变化时重算。 |
| 是否每 tick 扫描 | 无。 |
| 是否新增网络包 | 无。沿用方块实体本就同步的流体数据（内容变化时推一次）。 |
| 是否会加载区块 | 无。只用已加载方块实体或客户端登记表，绝不为判定加载远处区块。 |
| 内存 | 每个客户端登记表条目一个字符串（罐位置），可忽略。 |
| 延迟 | 同步滞后一两 tick + 网络延迟；极端"刚抽完立刻点"由服务端裁决，不会错扣。 |
| 与旧毒化 bug 的差别 | 旧实现缓存服务端标量（过期即永久错）；新实现每次从同步流体量现算，且未知不判灰。 |

## 根因分析与教训

1. **"未知"与"零"必须区分**：毒化 bug 的本质是把"没有信息"当成"空"。本轮把这一点编码成两种状态（`hasSyncedData`、`TankRef.loaded() == null`），两者都退回"交给服务端"。
2. **同一判定要镜像同一顺序**：服务端"来源罐非空优先、否则目标罐"，客户端必须一样，否则会出现两端结论相反。空罐不算付款方这条也一并对齐。
3. **只有一侧能改的状态，只能单向改**：新 mixin 只把按钮置灰、不点亮，避免覆盖 Waystones 自己的置灰原因（例如目标是当前石碑）。
4. **性能靠"缓存稳定值 + 现算易变值"**：位置（稳定）进登记表，池值（易变）从同步流体量现算并缓存到方块实体，渲染路径上没有查询与分配。
