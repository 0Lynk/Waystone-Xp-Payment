# 流体身份归一：按对象问孪生，入罐只存静止形态

日期：2026-10-31
分支：`fix/fluid-identity-canonicalisation`
远程父提交：`988b543`

## 改了什么

**一期（查表与比较按对象归一）**

- 新增 `src/main/java/com/olynk/waystonexppayment/fluid/FluidIds.java`：唯一的身份归一口。
  - `canonical(Fluid)`：`instanceof FlowingFluid` → `getSource()`，否则原样返回；`getSource()` 返回 null 也原样返回。
  - `canonical(FluidStack)`：重整到静止形态并保留组件（`applyComponents`），已经是静止形态时返回原对象。
  - `idOf(FluidStack)`：静止形态的注册 id。
  - `hasDistinctStillForm(boolean, boolean)`：包级纯判定，唯一的分支，便于无注册表单测。
- `fluid/FluidRates.java`：`idOf` 改为委托 `FluidIds.idOf`；`describe` 在原始 id 与静止 id 不同时两个都打印（`flowing_x (still form x) -> ...`）。
- `recipe/XpFluidRecipe.java`：`matchesFluid` 改用 `FluidIds.idOf(stack)` 与声明 id 比较，删掉 `BuiltInRegistries` 的直接使用。
- `fluid/FluidRateTable.java`：`counterpartId` 的文档降级为「兜底」，并写明三个分支各自对应的真实 mod（原版/CEI 前缀、Cyclic 后缀、Ender IO 成对）。

**二期（入罐归一 + 存档迁移）**

- `block/entity/XpPaymentTankBlockEntity.java`：
  - 匿名 `FluidTank#fill` 在 `super.fill` 之前把 `resource` 重整为静止形态，拒绝提示也用重整后的 stack。
  - `loadAdditional` 在 `readFromNBT` 之后、`clampLoadedPoolToCapacity` 之前调用新增的 `canonicaliseLoadedFluid()`：旧存档里的流动 id 原地改写为静止 id，打一行 INFO 说明，容量与经验值不变。

## 为什么改

罐里的流体身份此前只在**字符串层**猜：`counterpartId` 按命名规律翻孪生 id。这套规则在真实整合包里必然错一半——同一个整合包里 Cyclic 用 `xpjuice` / `xpjuice_flowing`（无 `_still`），Ender IO 用 `fluid_xp_juice_still` / `..._flowing`，原版与 Create Enchantment Industry 用 `flowing_` 前缀。猜错的后果不是报错，而是「罐里明明有经验流体，按钮却是灰的、也付不了钱」。

Create 与 Ender IO 的源码都证明：**id 字符串从来不是判断流体身份的正确层面**——Create 全程用 `FluidStack.isSameFluidSameComponents`，需要静止形态时问 `BaseFlowingFluid#getSource()`；Ender IO 干脆只生产 `source()` 形态。两者都用流体对象，不用名字。

## 改动前后对比

| 场景 | 改动前 | 改动后 |
|---|---|---|
| 管道灌入 `flowing_experience` | 罐里存流动 id，查表要靠命名猜中 | 入罐即存 `experience`，精确命中 |
| 罐里装 Cyclic `xpjuice_flowing` | 猜成 `xpjuice_still`，查不到 → 不能付款 | 问对象拿到 `xpjuice`，正常付款 |
| 单形态流体（Industrial Foregoing） | 前缀兜底可能猜出不存在的 id | `instanceof` 不成立，原样返回 |
| 旧存档里已有流动 id | 永远按未登记处理 | 载入时原地改写成静止 id，量不变 |
| `describe()` 与界面名字 | 可能显示玩家从未灌过的 id | 同时给出原始 id 与静止 id |
| 非 `FlowingFluid` 的注册方式 | 只靠命名 | 命名兜底仍在（三种拼法） |

## 备选方案

- **a. 只补命名规则**（加更多前后缀分支）：成本最低，但补不完——三种拼法之外还有单形态注册，每个新经验流体 mod 都是一次玩家报障。
- **b. 只在查表时用 `getSource()`（本次「一期」单独上线）**：能修「付不了钱」，但罐里仍是流动 id，界面名字、JEI、其他 mod 的过滤器依旧分叉。
- **c. 只在入罐时归一，不做一期**：`TankPoolIndex`、`matchesFluid`、`isSameFluidSameComponents` 三条通道里仍有两处要比原始 id，一处漏改就回到原点。
- **d. 按标签声明（`#c:experience`）**：上一版刚删掉，理由是标签与 id 会互相覆盖、优先级说不清；不重复引入。

选 **b + c 一起**（本次实现）：一期保证「同一个物质在任何通道都算出同一个答案」，二期保证「罐子里只存一种 id」，两者缺一都会留下分叉。

## 意外点

1. `FluidStack(Fluid, int, DataComponentPatch)` 构造器不公开可用（编译不过），必须 `new FluidStack(fluid, amount)` + `applyComponents(patch)` 才能保留组件。
2. `FlowingFluid#getSource()` 在 1.21.1 的抽象基类上就有，`Source` 与 `Flowing` 都实现它；因此不需要像 Create 那样再判 `BaseFlowingFluid` 子类型，`instanceof FlowingFluid` 已经覆盖两者。
3. 归一放在 `fill` 而不是 `drain`：出口保持不变，别的管道不会看到流体身份在抽取时变化。
