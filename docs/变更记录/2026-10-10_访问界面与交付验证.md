## 为什么改

1. 用户需求第 8 条要求"授权管理"可在游戏内完成，仅靠命令不可用。
2. FTB Teams 的 maven 仓库在本机不可达，而 Gradle 遇到仓库传输错误会**直接判定该模块解析失败**（不会继续
   尝试下一个仓库），因此构建被拖死；FTB 属于可选软依赖，反射化后构建不再需要它的仓库。
3. 规则 9 要求"报 DONE 必须附验证清单"，因此把构建/单测/冒烟的实际情况写成 `docs/verification.md`。

## 改动前后对比

| | 改动前 | 改动后 |
|---|---|---|
| 授权管理 | 仅 `/waystonexppayment access ...` 命令 | 空手右键储罐打开界面；命令仍保留（适合 RCON/自动化） |

## 根因分析与教训

1. **Gradle 的仓库错误语义**：仓库 404 → 继续尝试下一个仓库；仓库**连接超时** → 该模块解析直接失败。
   所以在"某仓库不可达"的网络里，唯一的解法是让构件在更靠前的可达仓库命中（内容过滤/本地镜像），
   而不是指望 Gradle 自动兜底。
2. **软依赖不要用编译期 API**：编译期依赖会把"可选"变成"构建必需"。反射让可选依赖真正可选，
   代价是 API 漂移要在运行时发现，因此必须显式记日志降级。
3. **冒烟测试的阻塞是环境而非代码**：`gradle runServer` 走到 `:prepareServerRun` 才失败，缺的是
   `net.neoforged:DevLaunch:1.0.2` 与 `neoforge-21.1.8-moddev-config.json`（只在 neoforged maven 上，
   mavenCentral 为 404）。项目自身的 `compileJava`/`processResources`/`classes`/`writeServerLegacyClasspath`/
   `downloadAssets` 全部成功。
4. 打开界面不需要额外的 open-screen 数据：位置随状态包到达，这也让服务端 `/reload` 后界面依然可用。
