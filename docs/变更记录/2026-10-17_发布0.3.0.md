# 发布 0.3.0

日期：2026-10-17　状态：已发布

## 改了什么

- `gradle.properties`：`mod_version` 0.2.0 → **0.3.0**，产物更名为 `waystone_xp_payment-0.3.0+mc1.21.1.jar`。
- `CHANGELOG.md`：把 `Unreleased` 段（图标条目）并入新的 `## 0.3.0 - 2026-10-17`，并补齐 v0.2.0 之后全部改动
  （远程目的地罐、提示包授权三态、协议 4、操作员编辑、下线玩家名、写侧上限、坏 UUID 连坐、载入裁剪、文档对齐）。
- 仓库根标签 `v0.3.0`（轻量标签，与 v0.1.0 / v0.2.0 一致），GitHub Release 附 jar。

## 为什么是 0.3.0 而不是 0.2.1

提示包（tank hint）新增了 `access` 字段，**协议版本 3 → 4**：0.2.0 的客户端读 0.3.0 服务端的包会错位，反之亦然。
按语义化版本，网络协议不兼容属于次版本号变化；0.2.1 会让人以为可以只更一端。

## 与上一版对比

| | 0.2.0 | 0.3.0 |
|---|---|---|
| 协议版本 | 3 | 4 |
| 单元测试 | 55 | 101 |
| 目的地罐 | 只认已加载区块 | 未加载时用槽位索引预览 |
| 无权限玩家的提示 | 照样回池量、按钮可亮 | `DENIED` 且池量为 0，客户端不视为付款方 |
| 操作员编辑他人罐 | 服务端允许、界面禁用（不一致） | 两侧同用 `canEditOrOp` |
| 下线成员显示 | 36 字符 UUID | 档案缓存名 → 8 位短 id |

## 根因与取舍

- 0.2.0 把「谁能编辑」「玩家叫什么」两层规则各写了多份，界面与服务端分叉是必然结果；0.3.0 把它们各收敛到一处
  （`canEditOrOp`、`PlayerNames#label`），代价是 `net` 包依赖 `auth` 工具类。
- 远程目的地罐本可以用「推送更新」在各端缓存池量，最终选择服务端索引 + 客户端按需询问：宁可让预览略微陈旧，
  也不给每个罐增加一份必须保持同步的存档数据（`TankPoolIndex` 是可重建缓存，不入存档、不升 DataVersion）。

## 验证

- `gradle test --offline` → 101 tests / 0 failures / 0 errors。
- `gradle build --offline` → BUILD SUCCESSFUL；产物大小与 sha256 见 Release 正文。
- 冒烟 `runServer`：mod 初始化、payload 注册、mixin 应用均无报错（`Done` 阶段受机主正式服务器占用 25565 限制）。
- 三处测试环境（服务端 + 两个客户端）部署同一 jar，sha256 逐一比对一致。

## 风险与未覆盖

- 实机复测两项（操作员编辑他人罐、下线成员显示名字）在发版时仍由机主执行中；本版按代码与单测证据发布。
- 编辑/查询无距离校验（D9）未修；队伍行对非本人队伍仍显示团队 UUID。
- FTB Teams 成员面板与注册握手仍未在有 FTB Teams 的机器上验证。
