# 命令回执搬进语言文件（2026-11-03）

## 改了什么

`/waystone_xp_payment access …` 的九条玩家可见回执过去是 `XppCommands.java` 里的 `Component.literal(...)` 硬编码英文，
而同一命令树的五条错误消息早就走 `commands.waystone_xp_payment.*`，于是玩家会看到「英文回执 + 中文报错」混排。

| 位置 | 改动前 | 改动后 |
|------|--------|--------|
| 罐摘要 | `Component.literal(pos + " : " + fluid + " ... " + poolXp)` | `commands.waystone_xp_payment.info.tank`（9 个参数） |
| 仅有名字的旧条目 | `Component.literal(count + " legacy name entry/entries ...")` | `commands.waystone_xp_payment.info.legacy`（1 个参数） |
| 逐条玩家／队伍 | `Component.literal("player " + name + " " + uuid)` | `info.player` / `info.team`（2 个参数） |
| 模式回执 | `Component.literal("Tank access mode is now " + (whitelist ? "whitelist" : "blacklist"))` | `mode.changed` + 复用界面已有的 `access.mode.whitelist` / `access.mode.blacklist` |
| 添加／移除玩家、队伍（8 条） | `Component.literal(...)` | `add.player`、`add.player.already`、`remove.player`、`remove.player.none`、`add.team`、`add.team.already`、`remove.team`、`remove.team.none` |

配套：

- `en_us.json` / `zh_cn.json` 各新增 13 条 `commands.waystone_xp_payment.*`。
- 删除死键 `commands.waystone_xp_payment.no_permission`：全仓只有 `access.no_permission` 被引用
  （`net/XppServerHandler.java:182`），这条命令级权限文案从来没有显示过（命令树用的是 `requires(hasPermission(2))`，
  未授权时由原版发话）。
- `access.add_team` 英文由 `+ Add teams` 改为 `+ Add my team`，与中文「+ 添加我的队伍」对齐。
- 新增 `src/test/java/com/olynk/waystonexppayment/lang/LangKeysTest.java`（4 例）做回归守卫。

## 为什么改

机主指出「9 条命令回执搬进 lang，语言支持不用声明；语义漂移修一下，中文『添加我的队伍』能放下，那么英文
『Add my team』也能放下」。前两点是同一件事的两半：**玩家可见文本必须只有一个来源**。硬编码英文字面量不会随语言
切换，也不进翻译流程——任何人想加一种语言都得改 Java。

## 改动前后对比

- 语言切换：改前英文回执在任何语言下都是英文；改后跟随客户端语言。
- 术语：改前命令说 `whitelist/blacklist`、界面说「白名单/黑名单」；改后共用同一批键，只有一套词。
- 参数：改前靠字符串拼接，参数顺序写死在代码里；改后由 lang 的 `%s` 位置决定，译者可调整语序。
- 流体名：`info.tank` 传的是 `Component`（`getHoverName()`），不是 `.getString()`，所以流体名本身也会按语言渲染。

## 备选方案

- **a. 只搬九条、不加测试**。最小改动，但「改了英文忘了中文」这类问题下一轮还会复发，且没有任何东西会红。
- **b. 保留 `no_permission` 死键**。无害但会让人以为还有一条权限文案在生效；测试加了却查不出死键（只比对两侧集合，
  不比对代码引用），所以顺手删掉。
- **c. 断言英文文件是纯 ASCII**。做不到：现有 `en_us.json` 含 `—`、`·`、`…` 等排版符号，断言纯 ASCII 会立刻误报。
  改成「英文文件不得含中日韩字符」。
- 选定：a 的改动 + b 的清理 + c 的弱化版本（EN 无 CJK、ZH 每一条都要有 CJK）。

## 意外点

1. `commands.waystone_xp_payment.no_permission` 是死键——两侧集合一致不代表都被用到，集合比对查不出这类问题。
2. 英文语言文件不是纯 ASCII（破折号、间隔号、省略号），所以「英文侧不得出现中文」只能查 CJK 区段，不能查「非 ASCII」。
3. `access.mode.unknown` 的值是 `...`，两侧完全相同——「中文必须含中文」的断言必须跳过没有拉丁字母的行，否则它自己会红。
4. 模式名不能新造词：界面用的是 `access.mode.whitelist`/`blacklist`，命令树必须复用，否则同一状态在两张屏上会有两个名字。

## 未覆盖

- 语言文件只在 JUnit 里被读，没有实机启动验证过渲染（键名正确性由 `LangKeysTest` 与 grep 兜底，实机表现需重新进游戏看一眼
  命令输出）。
- 只支持 `en_us` 与 `zh_cn`；新增语言仍需手工加文件（`LangKeysTest` 会强制它与英文键一致）。
