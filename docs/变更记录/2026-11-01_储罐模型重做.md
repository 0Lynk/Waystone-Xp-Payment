# 储罐模型重做：从纯色方块换成玻璃骨架罐

- 日期：2026-11-01
- 范围：`assets/waystone_xp_payment/models/block/xp_payment_tank.json`、`textures/block/xp_payment_tank_frame.png`、`textures/block/xp_payment_tank_glass.png`；删除 `textures/block/xp_payment_tank.png`

## 改了什么

机主在 Blockbench 里做的罐子模型（`D:\Desktop\model`）有六处问题，逐条修掉后入库：

| # | 原模型 | 现在 |
|---|--------|------|
| 1 | 6 块玻璃是零厚度平面（`from`/`to` 两点同值） | 每块给 0.02 厚度：两侧都能看到，且各自由正确的一侧受光 |
| 2 | 贴图引用是裸名 `texture` / `texture1` | 改成 `waystone_xp_payment:block/xp_payment_tank_frame` / `..._glass` |
| 3 | 没有 `parent` | `minecraft:block/block`（顺带给到物品栏、地面、手持的 display 变换与 `gui_light: side`） |
| 4 | `texture_size` 写 64×64，与实际贴图不符 | 直接沿用机主两张图的实际尺寸，模型不再声明尺寸 |
| 5 | UV 大幅拉伸（16×1.5 的横梁用 0.75×8 的 UV 区域） | 骨架统一 `uv: [0,0,16,16]`；玻璃沿用机主自己的两处 UV 区域，见下 |
| 6 | `model.json:64` 写成 `14.6` | 14.5，与其它三根立柱对齐 |

另一处是我按经验加的：玻璃用 `render_type: minecraft:cutout`——贴图只有全透明与不透明两种像素，不需要 `translucent` 排序。

## 玻璃的六个面（第二轮按机主反馈修正）

第一版我删掉了顶面、并把六块玻璃内缩到 `1.55 … 14.45`，机主看过后指出三处不对，全部改回他的布局：

| 机主反馈 | 原因 | 修正 |
|----------|------|------|
| 顶面没有 | 我按「液面将来由渲染器画、顶盖会挡住」自作主张删了 | 恢复顶面，六块玻璃齐全 |
| 外壁位置被改了，应该接在框架上 | 我把玻璃内缩到 1.55，与 1.5 的骨架之间留了缝，看起来是「盒子里再套一个小盒」 | 玻璃改成机主的 `1 … 15`，边沿埋进骨架，视觉上贴在框架上 |
| 底面不是我画的那个底面 | 机主的 `texture1.png` 里有**两幅**14×14 图案：侧壁用第一幅 `uv [0,0,3.5,3.5]`，顶/底面用第二幅 `uv [3.75,0,7.25,3.5]`；我把六面都用了第一幅 | 六面按机主原本的分区取贴图：四个侧面 `[0,0,3.5,3.5]`，顶面与底面 `[3.75,0,7.25,3.5]` |

## 两张贴图的处理

| 文件 | 实际内容 | 处理 |
|------|----------|------|
| `texture.png` | 32×32，整张一个颜色 `(87,95,116)` | 原样拷成 `xp_payment_tank_frame.png`；每像素同色，UV 怎么铺都一样 |
| `texture1.png` | 64×64 透明底，左上角两幅 14×14 图案（第一幅 x 0–13，第二幅 x 15–28） | 原样拷成 `xp_payment_tank_glass.png`，不做重排；模型用 UV 精确取这两块 |

（第一版曾把玻璃重排成 16×16 单块，因为当时只打算用一个面。既然后来要按机主的六面分区取图，保留原始 64×64 更忠实。）

## 美术与几何约定

- 玻璃图案中间是透明的，这是机主的设计；因此空罐从上往下看能透过底面看到草地——不是渲染错误。若要有实心底板，需要另加一块挡板或把底面换成骨架贴图。
- 一个方块面吃一整张贴图；改图时保持 16×16（或 32×32/64×64 等方形），图案位置与 UV 对应。
- `cutout` 只认 alpha 0 与 255，半透明像素会被当作全不透明。

## 备选方案

- **a) 零厚度 + 复制翻转另一面**：能省 6 个面，但镜像面要单独配 UV，且两面之间会有 0.001 的 z-fighting 风险。
- **b) 只做外壁、内壁交给方块自身的背面**：Minecraft 面剔除按 `cullface` 判定邻居遮挡，不是背面剔除；透明模型的内侧本来就会画，方案 b 不解决问题。
- **c) 保留「六面都用第一幅图」**：省事，但顶/底面会与机主画的那幅不一致——正是他这次指出的问题。

## 意外点

- `minecraft:block/block` 里确实带着 `display` 全套变换与 `gui_light: side`（从客户端 jar 的 `assets/minecraft/models/block/block.json` 读到），所以只写一句 `parent` 就把物品栏、手持、掉落物三种绘制都修好了；`cube_all` 反而只是个贴图别名外壳，没有 display 信息。
- 机主在 `texture1.png` 里画了两幅几乎一样的图案，第一版误以为其中一幅多余；实际是他的模型用两段 UV 分别取给侧壁和顶/底面。
- 模型 JSON 由一次性 Python 脚本生成（不进仓库），文件约 20 KB，可读性换体积。

## 验证

- 18 个元素（12 骨架 + 6 玻璃），无零厚度元素，坐标全部落在 0–16。
- 模型 JSON 可被解析，`parent` / `render_type` / `textures` 三项齐全；六个玻璃面各自带着 `uv`。
- `.\gradlew.bat build --offline` → `BUILD SUCCESSFUL`，jar 内包含模型与两张贴图，旧贴图已不在包里。
- 用等轴测预览（Python + Pillow 软件光栅器，一次性脚本，不进仓库）把真实贴图逐像素贴到每个面上渲染过：骨架、六面玻璃、内部液面位置正确。

## 未覆盖

- **没有在游戏里看过**：模型是资源文件，服务端冒烟测不到渲染。
- 液面渲染还没做：罐内流体目前不可见，要等 block entity renderer（已调研：按 Ender IO 的做法自绘 UP + 四侧 5 个面）。
