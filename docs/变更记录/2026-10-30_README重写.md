## 为什么改

机主（m07442）给了一版口述结构调整，要求：把「目标罐」这一级付款写进用法、把命令单独成节、把 AI 免责声明拆成
四段（AI 生成内容 / 代码质量约束 / 项目管理纪律 / 可维护性约束），并强调「基于真实整合包游玩反馈」。

实际缺陷是三条：① 支付顺序只写了「源罐」，读者不知道目的地罐也参与；② 命令散落在所有权小节里，OP 找不到；
③ AI 声明是一整段散文，读不出「过什么门禁」。

## 改动前后对比

- 支付顺序：改动前只有「源罐先付、不足由玩家付」；改动后四步齐全，并写明两者都不够时**取消且不扣任何东西**。
- 门禁：改动前 55 tests 已过时；改动后写明「140 tests across 22 suites」，含 `MixinShadowPolicyTest` 这类守卫测试。
- 版本：改动前顶部写 21.1.45+、安装节写 21.1.46+，自相矛盾；改动后统一为「21.1.45 or newer（built and tested
  against 21.1.46）」，与 `gradle.properties` 的 `waystones_version_range=[21.1.45,)` 一致。

## 备选方案

- a) 只加「目标罐」一句、其余不动：改动最小，但命令与 AI 声明仍然找不到，问题会再来一次。
- b) 整篇照抄机主口述：口述是提纲（如「Waystones 21.1.46 or newer」与我们 metadata 的 `[21.1.45,)` 冲突），照抄会把
  版本要求写死成错值，故按其结构重写、事实按代码校准。
- c) 拆成多文件（README + docs/usage.md + docs/commands.md）：对外门面被拆散，新访客要跳转三次，与「漏斗」相悖。
- **采用 b**：结构照机主，事实照代码。

## 意外点

- README 是英文，而 `docs/` 是中文——这不是混用事故，是 `AGENTS.md`「## 语言约定」的分层：文档目录中文、对外门面与
  git 历史英文；`.github/scripts/check-language.py` 只扫 `src/ tools/ gradle/ .github/` 与根 gradle 文件，不扫 README。
- `remoteDestinationPayments` 与 `remotePaymentChunkLoadsPerTeleport` 都在 `[tank]` 段而不是 `[payment]` 段（配置代码
  `builder.push("tank")` 在二者之前），照 `[payment]` 写会误导读者在错误小节找键。
- 版本行本身是历史遗留矛盾（顶部 21.1.45+ / 安装节 21.1.46+），这次顺带对齐到 metadata。
