## 为什么改

用户实测：**右键储罐后服务器直接崩溃 / 掉线**。日志给出两条互相独立的证据链：

```
[21:48:29] [Netty Acceptor IO Thread/ERROR] Exception caught in connection
io.netty.handler.codec.EncoderException: Failed to encode packet 'clientbound/minecraft:custom_payload'
Caused by: java.lang.RuntimeException: Failed encoding custom payload waystone_xp_payment:tank_state:
  io.netty.handler.codec.EncoderException: Empty FluidStack not allowed
...
[21:48:29] Dr_Dogey lost connection: Internal Exception: ... Failed to encode packet 'clientbound/minecraft:custom_payload'
```
```
[21:48:29] [Server thread/WARN] [com.olynk.waystonexppayment.auth.TeamResolvers/]:
  FTB Teams is installed but its API could not be used, team-based tank access disabled
Caused by: java.lang.NoSuchMethodException: dev.ftb.mods.ftbteams.api.FTBTeamsAPI.isManagerLoaded()
```

即：右键打开界面时会发送 `waystone_xp_payment:tank_state`，而**空罐**时该包用非空编解码器编码流体 →
抛异常 → 数据包发送失败 → 玩家被断开（单人游戏里表现为"服务器崩溃"）。FTB 那条是被我们捕获并降级的
WARN，本身不崩，但说明队伍功能当时是关掉的。

## 改动前后对比

| | 改动前 | 改动后 |
|---|---|---|
| 空罐右键 | 编码 `Empty FluidStack not allowed` → 断开连接 | 空罐编码为 varint 0，正常打开界面 |
| FTB Teams | 反射找 `FTBTeamsAPI.isManagerLoaded()` → `NoSuchMethodException` → 降级"仅玩家" | 反射目标为 `FTBTeamsAPI$API`，队伍功能可用 |
| 证据 | 只有用户描述 | NeoForge 源码 `FluidStack.java:123-142`（非空 `STREAM_CODEC` 明确抛 `EncoderException`）+ `94-119`（`OPTIONAL_STREAM_CODEC` 用 0 表示空） |

## 根因分析与教训

1. **NeoForge 的流体有两个流编解码器，语义相反**：`STREAM_CODEC` = 非空，`OPTIONAL_STREAM_CODEC` = 允许空。
   我们的状态包要能表达"罐是空的"，就必须用后者。凡是"可能为空"的流体/物品栈过网络，都要先确认编解码器
   是否接受空值——这类错误只有在**运行时**、且恰好是空罐时才会触发，编译期与单测都看不见。
2. **`javap` 要核对到"声明该方法的类"**：我当初确实 javap 过 FTB 的 API，但看的是
   `FTBTeamsAPI$API` 的输出，代码里却把方法名挂在 `FTBTeamsAPI` 外层类上；两者名字只差 `$API`。
   教训：反射代码里的类名/方法所属类必须与 javap 输出**逐字**对应（嵌套类要带 `$`），并在真实 jar 上
   跑一次解析探针（本次已补 `FtbProbe`，逐项打印解析到的 Method）。
3. **客户端侧失败会伪装成"服务器崩溃"**：数据包编码异常发生在 Netty IO 线程，玩家被踢回主菜单，
   而真正的堆栈在 `logs/latest.log` 的 `Exception caught in connection` 附近。修 bug 先看这条，而不是
   先怀疑世界或方块实体逻辑。
