# 测试流程（waystone_xp_payment）

日期：2026-10-16
适用：0.2.0 之后的每一轮改动，以及每次发版前的验收。
配套：`docs\问题修复清单.md`（每条缺陷对应的验收用例编号一致）。

**两条基本原则**

1. **先记录，后修复**：发现不符合预期时，先把现象、日志、截图固定下来，再动代码 —— 否则现象会被修复动作掩盖。
2. **证据不靠回忆**：每个用例的结论必须附「截图 / 日志片段 / 命令输出」之一，只写「试过了，正常」不算通过。

---

## 1. 测试分层

| 层级 | 环境 | 谁来做 | 说明 |
|---|---|---|---|
| **L0 静态与构建** | 命令行 | 主会话 | 构建、单测、产物 sha256、jar 内容、文档与源码一致 |
| **L1 单元测试** | 命令行 | 主会话 | `gradlew test`；纯逻辑类（付款拆分、流体倍率、菜单布局……） |
| **L2 无头集成** | `runServer` + RCON | 主会话 | 服务端启动、注册、存盘往返、数据包编解码；**尚无自动化，待补** |
| **L3 客户端单机** | 游戏客户端 | 机主（你） | 界面、交互、单人传送付款、存盘 |
| **L4 多人** | 专用服务器 / 局域网 | 机主 + 一名玩家 | 名单授权、并发、越权、拒绝回执 |
| **L5 兼容矩阵** | 多个依赖版本 | 机主 | Waystones 版本、FTB Teams 有无、与其他模组共存 |

## 2. 环境与准备

**构建（在沙箱外执行）**

```powershell
$env:GRADLE_USER_HOME='D:\deepseek\.gradle-home'
$env:JAVA_TOOL_OPTIONS='-Duser.language=en -Duser.country=US'
cd D:\deepseek\waystone_xp_payment
.\gradlew build --offline
```

**测试实例**：`D:\Minecraft\ShatteredPrism-Windows-MinGW-w64-Portable-1.9.1\instances\中毒机霸症\minecraft\`

**开工前必做**

1. 备份 `mods\` 与 `saves\`（换 jar 前）。
2. 记录本次环境：游戏版本、Waystones 版本、FTB Teams 版本（有/无）、其他相关模组版本。
3. **完全退出客户端**再换 jar（半退出状态下 mixin 仍会用旧 jar）。
4. 清空 `logs\latest.log` 或记下开始时间，方便回看。

**取证命令**

| 目的 | 命令 / 方式 |
|---|---|
| 看罐内流体与名单 NBT | `/data get block <x> <y> <z>` |
| 看玩家经验值 | `/xp query <玩家> points` |
| 罐子信息 | `/waystonexppayment info`（需权限等级 2） |
| 名单改模式 | `/waystonexppayment access mode whitelist\|blacklist` |
| 加/减条目 | `/waystonexppayment addplayer\|removeplayer\|addteam\|removeteam <名>` |
| 崩溃与异常 | `logs\latest.log`、`crash-reports\`（找 `Mixin apply failed`、`Exception`、`Payload`） |
| 视觉 | 截图（界面、模组列表图标、传送按钮状态） |
