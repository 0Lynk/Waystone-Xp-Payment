# 契约：注册一种经验流体（数据包作者指南）

适用于 `waystone_xp_payment` 0.4.0 及以后。本文描述的是**稳定契约**：字段名与语义变更是破坏性变更，会在 changelog 中标注。

## 1. 它解决什么问题

Waystones 的传送要收经验。这个 mod 允许「经验流体储罐」替你付这一笔。它必须先知道：**哪种流体算经验、一桶值多少 XP。** 这个知识完全来自数据包。

## 2. 最小示例

路径：`data/<你的命名空间>/recipe/<任意名字>.json`

```json
{
  "type": "waystone_xp_payment:xp_fluid",
  "fluid": "create_enchantment_industry:experience",
  "xp_per_bucket": 1000
}
```

含义：`create_enchantment_industry:experience` 这一种流体，每 1000 mB（1 桶）值 1000 XP，即 1 mB = 1 XP（与 Create: Enchantment Industry 自身的换算一致，也是本 mod 内置表的取值）。

## 3. 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `type` | 字符串 | 是 | 固定 `waystone_xp_payment:xp_fluid` |
| `fluid` | 字符串 | 是 | 精确流体 id，`命名空间:路径`。**不支持标签** |
| `xp_per_bucket` | 数字 | 是 | 每 1000 mB 值多少 XP，允许小数 |

`xp_per_bucket` 的取值：

| 值 | 含义 |
|---|---|
| `1000` | 1 mB = 1 XP（最常见的「液态经验」） |
| `500` | 2 mB = 1 XP（稀释） |
| `2000` | 1 mB = 2 XP（浓缩） |
| `1` | 1 桶 = 1 XP（极稀） |
| `0` | **注销**：把这个流体从表里删掉，即使内置表登记过它 |
| 上限 `1000000` | 1 mB = 1000 XP，再高视为配置错误 |

## 4. 生效规则

1. **精确 id，不做模糊匹配。** 不认标签（`#c:experience` 无效），不认「名字里有 experience 就当经验」这类猜测。
2. **flowing / still 自动归一。** 声明 `x:xp_fluid`，则 `x:flowing_xp_fluid` 自动同率（反之亦然）；罐子被管道灌入时常拿到 flowing 变体。
3. **覆盖顺序由包优先级决定**：
   - 同一个配方 id 被多个包定义 → 后加载的包覆盖前面的（原版数据包语义）；
   - 不同的配方 id 声明同一个流体 → 包位置靠后的赢；同一个包内 → 配方 id 字典序靠后的赢；
   - 内置默认表位于最低优先级，任何数据包都能覆盖它。
4. **`xp_per_bucket: 0` 优先级最高**：一旦某个包注销了该流体，后续包再声明它会重新启用（按规则 3 的先后）。
5. 加载时对每条声明打日志（`declared <fluid> = <rate> XP/bucket (from <pack>: <recipe id>)`），冲突时额外一条 `WARN`。

## 5. 旧写法为什么失效

0.3.x 及以前：

```json
{ "type": "waystone_xp_payment:xp_fluid", "tag": "c:experience", "mb_per_xp": 1 }
```

- `tag`：已移除。标签命中多个、互相冲突时没有可解释的优先级，因此这一维被整个删除。
- `mb_per_xp`：单位反了（mB per XP），且只能是 ≥1 的整数，写不出浓缩流体。

现在写这两个字段的 JSON：**该条声明被跳过**，并在日志里输出一条 `ERROR`（说明期望字段名与单位），其余声明不受影响。

## 6. 取整规则（付款时）

金额用整数毫 XP 计算，规则固定：

- 罐里 mB → XP：`floor(mB × xp_per_bucket_milli / 1_000_000)`
- 需要 XP → 抽液 mB：`ceil(xp × 1_000_000 / xp_per_bucket_milli)`

也就是：**罐子永远不会为一次传送多付，也不会少收**；余量留在罐里。一次传送最多从罐里抽走它报得出的那些 XP 对应的 mB。

## 7. 内置表登记了哪些流体

见 `data/waystone_xp_payment/recipe/builtin/`（每个流体一个文件，文件名即流体路径）。目前覆盖：Create: Enchantment Industry、Beyond Dimensions、Sophisticated Core 的经验流体，以及 `c:experience` 标签下的常见实现。

想改其中任何一个：不需要动我们的文件，写一条同 `fluid` 的声明即可覆盖（规则 3）。

## 8. 自检

- 装好后看服务端启动日志：`Loaded N experience fluid rate(s)`，N 为最终生效条目数。
- 想看某个流体当前生效的费率：`/waystonexppayment info`（输出 `via <来源>`）。
- 若某流体没出现在日志里，先检查：`fluid` 拼写是否精确、`xp_per_bucket` 是否为数字、JSON 是否有语法错误（配方解析失败会在 `latest.log` 里留下原版解析错误）。
