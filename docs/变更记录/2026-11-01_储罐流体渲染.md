# 罐内流体渲染：动态贴图 + Create 式液面过渡

- 日期：2026-11-01
- 范围：新增 `client/XpPaymentTankRenderer.java`、`client/FillAnimation.java`、`src/test/.../client/FillAnimationTest.java`；改 `client/XppClientEvents.java`（注册渲染器）

## 改了什么

灌进罐里的流体以前完全看不见——罐子只有模型，没有 block entity renderer。现在：

1. **画出液体**：按 Ender IO 的做法自绘 5 个面（顶面 + 四侧），贴图取流体自己的 still 贴图，颜色取流体的 tint。
2. **贴图是动态的**：UV 走 `TextureAtlasSprite#getU/getV`，它返回的是**当前动画帧**的坐标，所以水、岩浆这类多帧流体进罐后照样流动，不需要我们自己做帧计时。
3. **液面平滑过渡**：Create 的罐子在升降时有过渡，EIO 的没有。新增 `FillAnimation`——指数缓动，时间常数 180 ms，约半秒走完 95% 的差；首帧直接吸附到真实液位（否则一进视野就像在自动灌水）。
4. **侧面贴图不压缩**：侧面 UV 只取贴图底部 `level` 高度那一段（`v = getV(1-level) .. getV(1)`），半罐时看到的是贴图下半部分，而不是整张贴图被压扁——压扁正是 EIO 那些廉价流体看起来「在翻滚」的原因。

## 为什么

机主的原话：EIO 和 Create 的罐内流体有动态贴图、并且和流体真实贴图一致；Create 的液面升降有过渡动画，EIO 没有；两者都要。

## 改动前后对比

| | 之前 | 现在 |
|---|------|------|
| 罐内有流体时 | 什么都看不见 | 液面高度与流体量成正比 |
| 贴图 | — | 流体自己的 still 贴图，动画帧自动跟随 |
| 液量变化 | — | 约 0.5 秒内平滑升降 |
| 空罐 | — | 什么都不画（`LOWEST_VISIBLE = 0.004` 以下视为空） |

## 备选方案

- **a) 照抄 Create 的整条渲染链**：Create 的 `FluidTankRenderer` 一次画完整个多方块、带窗口判定、`shouldRenderOffScreen()`，还要 catnip 的 `PonderRenderTypes`。我们是单方块、单流体，这些全是负担。
- **b) 用 `Sheets.translucentCullBlockSheet()`（EIO 的选择）**：开背面剔除，绕序写错就整块消失，且从罐内看内壁会缺面。改用不剔除的 `RenderType.translucent()`（原版水就是这么画的）。
- **c) 自己写 shader 做液面波动**：视觉效果更好，但要么加依赖，要么手写 GLSL，超出这一轮范围。

## 意外点

- `IClientFluidTypeExtensions.of(...)` **只接受** `Fluid`、`FluidState`、`FluidType`，没有 `FluidStack` 重载——要写 `of(fluid.getFluidType())`，再把它传回去的 `getStillTexture(FluidStack)` / `getTintColor(FluidStack)` 才能按 NBT/组件区分流体。
- 渲染器是**每个方块实体类型一个实例**，所以动画状态不能放在渲染器字段上，否则所有罐共用同一条缓动。改成 `WeakHashMap<BlockEntity, FillAnimation>`——罐子卸载时动画跟着回收。
- `RenderType.translucent()` 不剔除背面，所以四个面的顶点绕序即使写反也不会让液体消失；这也是我没有为绕序写测试的原因。
- 流体的 tint 高 8 位（alpha）在原版里恒为 0，直接拿去当透明度会让液体全透明；这里固定用 1.0，与原版流体渲染一致。

## 未覆盖

- **没有在游戏里看过**：渲染结果、液面高度、贴图朝向都需要机主实机确认。
- 液面高度的计算基准是「罐内腔从 1.02 到 14.98 模型单位」，与模型里的玻璃位置绑定；将来若改模型内腔尺寸，这里的常量要一起改。
