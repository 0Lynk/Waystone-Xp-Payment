# v0.2.0 发版准备：版本号提升、CHANGELOG 与 README 对账

日期：2026-10-11
版本：0.2.0
依据：用户要求（把 mod 版本号更新为 0.2.0，并提交新的 Release 到 GitHub）

## 改了什么

### 版本号

- `gradle.properties:13` 的 `mod_version` 从 `0.1.0` 改为 `0.2.0`。这是唯一的版本来源：`build.gradle:6`
  把它拼成 `version = "${mod_version}+mc${minecraft_version}"`，`:74` 交给 processResources，最终展开进
  `src/main/resources/META-INF/neoforge.mods.toml:8` 的 `version = "${mod_version}"`。
- 已核对构建产物：`build/libs/waystone_xp_payment-0.2.0+mc1.21.1.jar` 内的 `neoforge.mods.toml` 是
  `modId = "waystone_xp_payment"`、`version = "0.2.0"`。其余 `0.1.0` 字样只出现在历史文档（`CHANGELOG.md`、
  `docs/verification.md`、旧变更记录）里，属历史记录，不回改。

### CHANGELOG

- 新增 `## 0.2.0 - 2026-10-11` 段（Added / Changed / Fixed / Compatibility / Known limitations / Tests），
  覆盖 `v0.1.0..HEAD` 的 9 个提交：UUID 访问列表、一键加入我的队伍、所有者门禁与输入候选、快照到达前读
  state 的 NPE 与掉线、输入框打不进字、第三轮界面（选中 / 右键菜单 / 队伍成员面板）、传送列表首次打开即
  断线（mixin shadow 解析失败）、gradlew 可执行位。
- 0.1.0 段原文一字未改；「界面文案仅英文（硬编码）」这条旧限制改在 0.2.0 段里点名"已解决"。

### README

- 交互说明重写为第三轮行为：左键只选中；行尾 `···` 或右键开菜单（Add to list / Remove from list /
  View team members）；`Esc` 逐层退出（菜单 → 成员面板 → 过滤器 → 关屏）；表头状态条四态
  （Sending… / Applied / Refused by the server / No answer from the server）。
- 只读模式描述由"控件消失"改为"控件置灰"（实现是 `setActive(false)`，控件仍在）。
- 顶部 Waystones 版本要求 `21.1.46+` → `21.1.45+`（与 Compatibility 章节一致；编译仍对 21.1.46）。
- AI 声明里的单测数 `25 today` → `55 today`，并补上 mixin `@Shadow` 守卫测试。

### 发布

- 以本轮的 `main` 提交打 tag `v0.2.0`，建同名 Release，并附上新构建的
  `waystone_xp_payment-0.2.0+mc1.21.1.jar`；Release 说明沿用 0.1.0 的英文骨架（What's inside / Install /
  Known limitations / AI disclosure）。
- 新 jar 覆盖测试实例 `mods` 目录里的 0.1.0 jar，源/目标 sha256 一致后请用户完全重启客户端复测。

## 为什么改

用户要求把版本号提到 0.2.0 并发新 Release。发版前 `AGENTS.md` 要求补齐当轮变更记录，而仓库里的说明文件
仍停在 0.1.0 的状态：README 的交互说明还是第一/二轮行为（点候选即添加、行内 `×` 删除、`Esc` 两段），与
v0.1.0 之后三个界面轮次的实现相矛盾；单测数与 Waystones 版本要求也与实测不符。带着这些发 0.2.0，等于把
一份自相矛盾的说明发给用户。
